Why Amem exists

Long agent conversations waste tokens, drift, and hallucinate because context is re-fed from scratch every turn. Amem inverts that: every session is distilled into atomic knowledge units (dedup + link + consolidate), stored in a local knowledge graph, and recalled on demand as a compact, cited context block within a token budget. The result: agents re-locate past decisions without re-reading history, and memory compounds across sessions instead of evaporating.

Design principle: we rent the intelligence (any LLM provider), you own the memory — all data stays on your machine (SQLite, local embeddings, optional local LLM).

Core features

Ingest → distill
Traces become atomic units: dedup, embedding, auto-linking, consolidation into crystals.
Recall with budget
Assembled cited context block within a token budget; layered recall + working memory briefing.
Category management
8-category taxonomy (code/infra/workflow/product/personal/research/meta/other) — auto-classified on save, batch archive/restore/delete/accept in the Units console.
Knowledge graph
Force-graph UI colored by category, cluster arcs, scenario heat overlays, graph hygiene (bounded degree).
MCP server
stdio (default) + Streamable HTTP; Codex/Claude/Cursor agents call save_unit / recall / ingest / curate directly.
Auth & workspaces
OAuth2.1 (PKCE) + PATs with scope (read/write/admin, ws:<slug>:*), workspace-isolated storage, audit log.
LLM provider settings
Bring your own endpoint (OpenAI-compatible / DeepSeek / local vLLM) for distillation, classification, curation.
Docker one-command
docker compose up -d → Web UI + API + MCP on :8321, data in ./data.

Getting started

git clone → docker compose up -d (in docker/) → Web UI at http://127.0.0.1:8321 → register the MCP server in your agent config:

[mcp_servers.amem]
command = "npx"
args = ["-y", "amem-mcp", "--base-url", "http://127.0.0.1:8321", "--token", "amem_pat_..."]
